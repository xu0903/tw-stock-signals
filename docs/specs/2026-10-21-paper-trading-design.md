# 台股模擬交易系統設計

日期：2026-10-21　狀態：第 1–4 段已和使用者逐段確認，待使用者審閱本文件

## 目的與範圍

讓使用者用假錢、照真實台股規則練習交易：即時價格、真實五檔成交、手續費與稅、除權息、現股當沖、融資融券、追繳斷頭。

- **使用者**：先給使用者本人和受邀朋友。長期目標是做成給陌生人用的產品，並加上教學模式（另一個子專案）。
- **市場**：只有台股，上市與上櫃全部股票和 ETF（約 1,900 檔）。
- **不做**：期貨、選擇權、美股和日股、排隊與部分成交的模擬。
- **對外公開前必須解決**：證交所即時行情授權。依證交所收費表，在網路上提供自動更新的行情，5,000 戶以內每月 10 萬元。現階段只開放受邀者使用，報價寫成可替換的模組。

## 第 1 段：架構

```
iPhone ── 台股訊號網站（xu0903.github.io/tw-stock-signals）
            「模擬交易」分頁；個股詳細頁有「模擬下單」按鈕
            │ Supabase 登入（和 LifeMaster 同網域，登入狀態共用）
            ▼
Supabase（LifeMaster 現有專案 cvpcgqgpwelokwqltktd，獨立 schema `sim`）
  ├─ Edge Function `sim-order`：下單／取消。檢查規則，市價單用即時五檔立刻成交
  ├─ Edge Function `sim-match`：pg_cron 每 10 秒呼叫；交易時段內只抓「有掛單」的股票五檔來撮合
  ├─ Edge Function `sim-settle`：收盤後結算（取消未成交、當沖處理、利息、維持率、追繳、斷頭、除權息）
  ├─ Edge Function `sim-refdata`：每天開盤前更新股票清單、信用交易與當沖名單、除權息與強制回補日程、休市日
  ├─ Edge Function `sim-admin`：管理員入金、發邀請碼
  └─ `quote.ts` 報價模組：介面 getBook(symbols, session)。現在接證交所 mis 即時 API（整股 getStockInfo、零股 getOddInfo）
```

- 所有改動金額的動作都在後端執行。前端只能讀自己的資料（RLS），也只能呼叫上面的函式。
- 程式碼放在 `tw-stock-signals` repo：前端在 `web/`，後端在 `supabase/`（SQL migration 與 functions）。部署到 LifeMaster 的 Supabase 專案。
- 規則計算（費用、升降單位、撮合、維持率）寫成純 TypeScript 模組 `rules.ts`，不碰網路和資料庫，用 `deno test` 測試。

**帳號**：受邀才能開戶。管理員（使用者本人）發邀請碼；朋友登入後輸入邀請碼，就建立帳戶並得到 100,000 元。只有管理員能入金（給任何帳戶），每一筆入金都記在對帳單。帳戶分 `normal` 和 `tutorial` 兩種，`tutorial` 留給教學模式。

**分三階段上線**（每階段都能先用）：
1. 現股：整股、盤中零股、盤後零股；市價、限價；費用；除權息。
2. 現股當沖。
3. 融資融券（含追繳、斷頭、強制回補）。

## 第 2 段：錢怎麼算

### 費率預設（使用者指定「盡量悲觀」；每個帳戶都可在設定改）

| 項目 | 預設 |
|---|---|
| 手續費 | 成交金額 × 0.1425%，不打折；每筆最低 20 元（整股、零股皆同）；四捨五入到元 |
| 證交稅（賣出） | 股票 0.3%；ETF 0.1%；現股當沖賣出 0.15%（優惠到 2027-12-31）；資券當沖 0.3%；債券 ETF 2026-12-31 前免稅，之後 0.1%（修法延長後再改）；無條件捨去到元 |
| 融資利息 | 融資金額 × 7% × 天數 ÷ 365，從交割日算到償還日 |
| 融券手續費 | 融券賣出金額 × 0.1% |
| 融券擔保品利息 | 0%（不付利息） |
| 當沖先賣未回補借券費 | 日利率 3.5% × 回補成交金額 |
| 股利補充保費 | 單筆現金股利 ≥ 20,000 元時扣 2.11% |

費率參考：台新官網只寫「依牌告利率」，查不到具體數字，所以取各來源的悲觀值（國泰證券收費表、台新舊資料、業界常見範圍）。

### 買進力與交割

- 下單時就**圈存**「成交金額上限 + 手續費」（市價單用漲停價估算）。成交後按實際金額扣款，多圈的退回；取消或過期就解除圈存。
- 賣出所得在成交當下可以再用來買股票。對帳單同時顯示真實世界的 T+2 交割日。
- 現金不會變負數。任何會讓現金變負的動作都會被拒絕，斷頭和強制回補除外。

### 除權息

- 除權息交易日前一天收盤時持有的股數，才有配發資格（融資買進的也算）。
- 現金股利在發放日入帳；配股按「每股配股金額 ÷ 面額 10 元」換算股數，不足一股的部分照市場慣例折現，同樣在發放日入帳。
- 融券戶在除權息日要支付等額的股利和股票，從現金扣。

### 對帳單

`ledger` 每一筆都有 `code`（例如 `BUY`、`SELL`、`FEE`、`TAX`、`MARGIN_INTEREST`、`DIVIDEND`、`NHI_PREMIUM`、`ADMIN_DEPOSIT`），以及 `explain`（算式與參數）。教學模式之後可以直接拿來解釋每一筆錢的由來。

## 第 3 段：下單與成交

| 規則 | 做法 |
|---|---|
| 交易時間 | 整股 9:00–13:30；盤中零股 9:00–13:30，9:10 起撮合；盤後零股 13:40–14:30 委託，14:30 一次撮合；休市日依證交所行事曆 |
| 市價單 | 買進吃最佳賣價、賣出吃最佳買價，數量超過第一檔就往下吃；五檔都吃完還不夠，剩下的取消 |
| 限價單 | 掛著；撮合時對手價碰到委託價就用對手價成交（不會比限價差）；當天沒成交就取消 |
| 盤後零股 | 14:30 用當天公布的成交價撮合：買單限價 ≥ 成交價，或賣單限價 ≤ 成交價，就成交 |
| 漲跌停 | 五檔沒有對手單就無法成交 |
| 價格檢查 | 委託價要符合升降單位（10 元以下 0.01、50 元以下 0.05、100 元以下 0.1、500 元以下 0.5、1000 元以下 1、以上 5；ETF 50 元以下 0.01、以上 0.05），且在漲跌停之間 |
| 數量 | 整股以 1,000 股為一張；零股 1–999 股 |
| 報價中斷 | 抓不到報價或報價時間太舊（超過 30 秒）就不撮合，下單畫面顯示「報價中斷」 |
| 當沖 | 只限官方可當沖名單上的股票。先買後賣：收盤時沒賣掉的變成一般持股，照常交割。先賣後買：13:25 還沒買回就用市價強制買回，並收借券費 |
| 融資買進 | 只限官方可融資名單、整股。自備款：上市 40%、上櫃 50%（融資比例依名單上個股調整） |
| 融券賣出 | 只限可融券名單、整股。保證金 90% |
| 維持率 | 整戶擔保維持率 =（融資股票市值 + 融券擔保品與保證金）÷（融資金額 + 融券股票市值）。每天收盤後計算 |
| 追繳與斷頭 | 低於 130% → 發追繳通知；T+2 收盤前要補到 166% 以上（入金或賣股）；否則 T+3 開盤用市價處分，直到回到 166% 以上，或全部處分完為止 |
| 強制回補 | 依官方公告的股東會和除權息停券日，在最後回補日前提醒，期限到了就強制回補 |

## 第 4 段：畫面、教學預留、測試

**畫面**（在台股訊號網站裡）：
- 模擬交易分頁：帳戶總覽（現金、圈存、市值、未實現損益、已實現損益、總資產、維持率）、下單（即時五檔、整股或零股切換、市價或限價、現股／當沖／融資／融券）、委託、持股、對帳單、設定（費率）。
- 個股詳細頁：「模擬下單」按鈕。
- 管理員頁：入金、發邀請碼。
- 下單前顯示試算：預估手續費、稅、圈存金額；融資顯示自備款與追繳價。

**教學模式預留**：帳戶 `kind` 欄位；每筆 ledger 都有 `code` 和 `explain`；報價模組可以換成「歷史重播」來源（教學模式重播過去行情，沒有即時行情授權問題）。

**測試**：
- `rules.ts` 單元測試：每種費用和稅、升降單位、漲跌停、市價單逐檔吃單、限價撮合、盤後零股、維持率、追繳價、除權息換算。用真實案例，例如「融資買一張台積電 2,420 元，跌到多少會追繳」。
- 報價模組有假報價實作，整套下單→撮合→結算的流程不用等開盤就能測。
- 資料庫：RLS 測試（A 看不到 B 的帳戶，非管理員不能入金）。

## 已知限制與待辦

- 費率是悲觀假設，不是台新的實際牌告。
- 證交所 mis API 非官方文件，欄位或網址可能改變，報價模組要能快速替換。
- 每 10 秒撮合，比真實交易所慢；限價單成交時間可能晚幾秒。
- 有報導說盤中零股的首次撮合時間會在 2026-12-07 調整，實作時要再查證，交易時段寫成設定值。
- 部署 Edge Functions 需要使用者先執行一次 `supabase login`（之前已刪除 CLI 權杖）。
- 對外公開前：解決行情授權、資安稽核（LifeMaster 2026-10-01 稽核的未修項目也要一起看）。
